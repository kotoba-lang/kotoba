同じ名前に見えるものの境界

名前公開資料から読み取れる役割と限界
Kotoba開発中のLisp machineの言語・CLI。Amuはコンパイラ、Kototamaは実行契約。完全な統合機械が出荷済みという意味ではありません。Kotoba README
Awai Network / Awai Nodeネットワークと参加ホスト。登録だけでは参加承認・仕事の配置・報酬を保証しません。Murakumo README
Itonami業務意図、tenant、安定したjob ID、予算・期限を扱う層。Murakumoは配置と実行の計算プレーン。現在のMurakumo job契約にItonami期限が渡らないという制約があります。Murakumo README
Itonami OS（旧AWAI OS表示名）AIUEOSのAwai向けdistributionという採用済み方向。IDはawai。descriptor選択は構成メタデータを変えるもので、全アプリの導入・適格化や完成配布版の証明ではありません。Itonami OS ADR
公開network-awai/awai-osNixOSインストールメディア。AIUEOS系Itonami OSの完成イメージと読み替えてはいけません。実機、電話Passkey、推論には別の検証が必要です。Awai installer README

AIUEOSの旧リポジトリは現在shellで、OS本体・資料はKotoba内のlib/kotoba.aiueosへ移っています。古いリンクの404を「設計が消えた」と解釈せず、所有者と移転先を確認します。AIUEOS shell README

まず小さな成功と拒否を確かめる

Apple Silicon Macなら、公開Amuガイドの単一ファイル入門が具体的な入口です。以下は固定commitのガイドに基づく手順で、この原稿では未実行です。新しい作業ディレクトリを使い、既存出力を上書きしません。Amu Mac guide

git clone https://github.com/kotoba-lang/amu.git amu-mac
cd amu-mac
git checkout --detach 5c9aa0254bab5a23326823fcead72ec510e5715d
file -L bin/amu
shasum -a 256 bin/amu
codesign --verify --strict bin/amu
bin/amu check examples/foundation-starter/hello.kotoba
bin/amu compile examples/foundation-starter/hello.kotoba
bin/amu run examples/foundation-starter/hello.kotoba
bin/amu run ./hello

固定ガイドのCLI SHA256は 016aaefcac44eff3408fb30283aa5ab1125fb0ff0298d56ea23df621d67fc837。一致しなければ止めて原因を確認します。ガイドの期待値はcheckがok、runが42・exit 0。返り値を43に変えた別ファイルで再試験し、既存出力名・未知flag・不適合なmain型の拒否も記録します。これは公開CLI全体や独立ユーザーreleaseの適格化ではありません。Amu Mac guide

Itonamiの実ジョブは認可済みfleet・設定・予算が揃ってからです。公開Murakumo資料にはjobs submit/statusがありますが、汎用的なコマンドを無条件にコピーして共有fleetへ送らないでください。障害時unknownのジョブを勝手に再実行しないことも、二重作用を防ぐ使い方の一部です。Murakumo README

個人の成長・課題解決・社会への貢献をどう確かめるか

学習の具体例は、42→43の変更を説明し、許可されない操作の拒否理由を読めるようになることです。仮説は「AI出力をそのまま信用するより、再現可能な入力・出力・権限を確認する練習が理解を助ける」。学習前後の課題正答率、再現までの時間、拒否理由の説明正確性で測ります。改善率の実績は本資料からは確認できません。

組織の課題なら、定型処理一件について所要時間、修正時間、失敗・unknown・重複作用数、監査可能なreceiptの割合を導入前後で比較します。分散化の社会的価値も仮説です。可用性、参加に必要な機器費用、消費電力、運用負担、アクセス格差を同時に測り、参加ノード数だけを社会貢献の証明にしません。これは編集上の評価提案で、製品の達成実績ではありません。

速さと安全性は条件付きで読む

資料に記録された実測：Kotoba READMEは2026年10月15日のApple M4、19 Embench workloadでC実行時間の0.80倍を紹介します。コンパイラスナップショット、各workload一回、監査済みのアルゴリズム置換を含む結果です。現行release全体の速度、推論速度、他機種やすべてのプログラムの順位には一般化できません。この編集作業による追試でもありません。Kotoba README

実装の記述と設計目標：Mac入門は単一canonicalソース、mainの型、コンパイラdigest照合、実行時の再生成比較、子プロセスの5秒期限などを記述します。一般的なpackage・resolver・Darwin runtimeの完全互換は未完了です。権限を明示し未対応を拒否する方向でも、runtime・OS・鍵管理・配布経路は信頼基盤に残ります。「安全だから任意コードを無制限に動かせる」とは結論できません。Amu Mac guide Kotoba README

トークンの用途と価値が成立する条件

「トークン」には認証capability、サービス内credit、決済資産、取引可能な独自資産があり、同じものではありません。公開Murakumo READMEはBase/x402の限定USDC決済経路と、獲得creditの出金申請を説明しています。ただし申請成功はcreditを減算してoperator承認を待つ段階で、USDC送金の完了ではありません。旧chain ID 260425は廃止済みです。Murakumo README

独自トークンに持続的な需要が成立するには、実サービスへの必要性、品質と供給能力、手数料・発行量・配分、償還条件、運用費用、担保や不正時の扱いが検証可能である必要があります。市場価格にはさらに流動性、集中度、売却可能性が関係します。これは経済分析上の条件整理です。公開6資料だけではAwai独自トークンの現行発行条件、稼働市場、取引量、保有者収益は確認できず、値上がり・収益・元本を保証しません。

AIO用FAQ

Kotobaを最初に試す入口は？
Mac ARM64では固定Amuガイドのcheck/compile/run。古いHomebrewやkotoba -eをnative入門と混同しません。Amu Mac guide Kotoba README
Awai OSとItonami OSは同じ完成製品？
表示名の変更と、NixOSメディアの製品境界を区別します。AIUEOS distributionの完全releaseは別途適格化です。Itonami OS ADR Awai installer README
Itonami期限が計算を必ず止める？
公開Murakumoの現在のjob契約にはその期限が渡らないと明記されています。Murakumo README
ノード登録だけで報酬が得られる？
参加はpending admissionから始まり、配置・有料実行・収益は保証されません。Murakumo README
分散だから障害に必ず強い？
独立拠点での耐障害性と外部依存を個別検証する必要があります。公開資料の過去fleet snapshotは今日の稼働証拠ではありません。Murakumo README
出金申請は決済完了？
いいえ。記載されたpilotではoperator承認待ちです。Murakumo README
無料モデルなら鍵や非公開READMEも送れる？
この編集runnerは公開資料のみが対象です。無料価格は情報公開や保持条件への同意を意味しません。
AIOとは何を作ること？
ここでは定義、短い回答、条件、固定出典と更新日を読める形にする編集作業です。API送信によるupstream学習、検索掲載、推薦は保証しません。
