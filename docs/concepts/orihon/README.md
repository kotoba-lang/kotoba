# 折本 — アプリごとの表紙と、触れた折りをひらく OS UI 案（JUN-566）

## 核となる操作

**アプリをそれぞれ一冊の折本として並べる。表紙の触れた位置から、そのアプリだけをひらく。** 例えば、いとなみの下のほうに触れればその本の後ろの頁が開き、むらくもやあおぞらの表紙は閉じたまま。開いた折本では折り目を直接タップして任意の頁へ移る。複数の本を開いて並べることもでき、一冊を閉じても他の本は変わらない。

写真の表紙、厚み、山折り・谷折りの連続性を情報の構造へ翻訳する。表紙はアプリの入口、頁はアプリの機能、折り目は移動の取っ手。既存の native desktop とは別案であり、採用・置換を決めたものではない。

## 状態と入力

| 状態 | 見えるもの | 操作 |
| --- | --- | --- |
| 本棚 | アプリごとの閉じた表紙 | 触れた高さから対応する頁を開く |
| 部分展開 | 選んだアプリの表紙、選んだ頁と畳まれた折り目 | 任意の折り目をタップしてその頁を開く |
| 複数展開 | 複数アプリの折本が並ぶ | 独立して頁を選択・閉じる。幅が足りないときは横スクロール |
| 再開 | 閉じた本と最後に開いた頁 | キーボードで表紙を開くと前回の頁。ポインターなら触れた位置の頁 |

- タッチは表紙をタップした位置から頁を選ぶ。ホバーは不要。マウスもクリック位置で選び、クリック前に勝手に開かない。
- 開いた本には直接押せる各頁の折り目と閉じる操作を表示する。タブは矢印・Home・End、表紙はTab／Enterで使える。Escapeはその本を閉じる。
- 表紙のタップ領域は端だけの小さな目標にせず、本の高さを4つの選択領域に分けた試作。頁のタイトル表示や境界の拡大、触覚フィードバックは今後、実機で検証する。
- 再開頁の記憶は試作を開いている間だけ。閉じることはデータ削除でもセキュリティ上のロックでもない。
- 外部操作の確認は、接続先・操作・送る情報と許可／拒否を隠さない明確な面とし、操作ごとの本人の選択を共通ランタイムで扱う。試作には接続しない。

## 質感とアクセシビリティ

表紙は布・紙の手触りを思わせる色と細かな織り、頁は温かい紙色、選択した折りだけを少し広げて奥行きを示す。色だけに頼らず、頁名・開閉状態・フォーカスを明示する。実際の折り動作や効果音は将来の実機検証項目であり、音は初期オフを想定。OSの reduced motion と画面内切替で動きを抑えられる。大きな文字、画面読み上げ、キーボードのみの操作、縦・横画面、十分なタッチ領域を受入条件とする。

## 試作の境界

`index.html` はローカルのサンプルアプリ4冊を並べる、通信なしの静的ブラウザ試作。実OSアプリ、永続化、実際のデータ、外部接続、同意の実行、実機のタッチ評価は未実装。現在の native Kotoba/Amu GUI がHTML/CSSベースで完成しているという意味ではない。nativeレンダラや共有Browserへの反映、折り位置の連続操作、片手操作、性能と視認性の検証は別途必要。
