# AIUEOS user-v3 on current main (2026-10-26)

The AIUEOS Itonami diagnostic stack at
`7919191` was merged with `origin/main`
`ad501197077efe2a7684b26acec6105c1c12c549` in an isolated worktree.
The kernel and EFI were rebuilt from the merged AIUEOS source and the Mac
native Amu fixed point from [Amu integration #1595](https://github.com/kotoba-lang/amu/pull/1595)
at `111b64fbad93f548a931d57b18381cb6ee6c88d6`. The [font](font.json)
and user-v3 ELF were generated by the same signed Mac compiler. The builder
used 31 locked kernel modules and reproduced the ELF and EFI; its exact
source and artifact pins are in the [build receipt](build.json).

The [private-QMP three-boot receipt](debug-summary.json) and
[controller receipt](debug-run.json) record a password-free QEMU test:

1. Itonami accepted Goal `awai a` and committed it to an output-owned marked
   draft disk.
2. A fresh QEMU process restored the visible [Goal](restored-goal.png).
   The local-model [choice](approval.png) was denied once; that left user
   pages untouched. A fresh synthetic `y` then allowed the user-v3 ELF to
   create its 104-byte request and issue syscall 5 from CPL3. The returned
   token was 105, with no host-prefilled token.
3. A one-byte-modified user slot was refused at CPL0 before the model ran.

The QMP test used no VNC listener, password, NIC or human key entry. Synthetic
Y/N keys prove guest branching only; they do not establish trusted human
consent for an external operation. This is a fixed one-token local model,
not canonical `:llm/generate`, a full Itonami agent loop, a D2 workspace
restore, signed app admission, release qualification or a physical boot.
