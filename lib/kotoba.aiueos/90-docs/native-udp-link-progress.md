# Native QEMU UDP link — JUN-757

The opt-in `native/udp_link_gate.kotoba` exchanges complete Ethernet/IPv4/UDP packets between a native OS kernel and an independent Mac process. The Mac's UDP socket carries raw Ethernet frames through QEMU's datagram network backend. This exercises an emulated NIC's actual MMIO/DMA descriptors; it is not a socket capability supplied to an OS app, an installed Kekkai app, cryptographic peer authentication or physical6600H qualification.

`native/rtl8139_cplus.kotoba` is a distinct RTL8139C+ adapter, separate from the unchanged6600H RTL8168 driver. It enumerates PCI functions, admits the256-byte BAR1 through the existing PCI-MMIO mechanism, programs one TX and one RX descriptor in existing owned window10, verifies C+ mode before enabling TX/RX and polls without IRQs. RX buffers are1536 bytes; the driver checks ownership, complete-frame/error flags and bounds, removes the four-byte FCS from the delivered length and reposts the descriptor. The shared serializing fence orders ownership changes and DMA reads. TX accepts60..1514-byte Ethernet frames; its return means local descriptor completion, not end-to-end delivery. Neither the code cap nor a memory grant is enlarged. Unsupported devices have no legacy-ring fallback.

`native/ipv4_udp.kotoba` is a reusable, IO-free byte parser. `parse(frame,actual-capacity,wire-bytes)` rejects invalid Ethernet type, version, IHL, total length, TTL, protocol, reserved/fragment flags, header checksum, UDP length or nonzero UDP checksum. IPv4's optional zero UDP checksum is accepted. Checksums include IPv4 option bytes and odd UDP tails. The parser covers Ethernet frames through1514 bytes and IP packets through1500; options have length/checksum coverage, not general option semantics. Fragment reassembly, IPv6, ARP/DHCP/routing and other MTUs remain separate work. A successful scalar descriptor contains payload offset/length and ports; it grants neither a region nor endpoint/peer authority.

The test entry binds only the public fixture MAC/IP/port pair and echoes ten admitted frames. Swapping address/port pairs preserves the checksum sums; the Mac compares every returned byte with an independently constructed reply. Normal cases cover UDP payloads0/1/31/64/1280/1472, IPv4 header sizes24/60, a zero UDP checksum and DF. Twenty-one malformed or wrong-endpoint cases must be consumed and refused. The Mac waits for a guest acknowledgement published after descriptor reposting, so absence of an echo is not inferred merely from a timeout. All31 descriptors are consumed/reposted, all ten exact replies match and RX/TX/request boundary canaries survive, with no guest errors.

`scripts/native_udp_link_peer.py` is a public test-data oracle and observer. It uses only127.0.0.1 UDP sockets, never application secrets or a product backend. Both pre-test queued frames are preserved in full. The initial observer incorrectly attributed these two IPv6 frames to the first malformed probe and failed; the retained hashes exactly match the subsequent pre-test capture. That failed run remains failed. The corrected boundary leaves guest source and artifacts unchanged. The final driver additionally checks C+ readback and is independently rerun.

The source-locked16-module kernel retains the actual11 ValueRuntime sources and two PT_LOAD segments (RX345472B, RW2359296B), the2MiB generated-code cap and existing request/DMA grants. Native kernel/EFI/user ELF/slot reproduce, diagnostic user code is not executed, and the media remains unchanged. The three separately built IP-checksum/UDP-checksum/fragment faults must complete normally and be detected by actual bad-packet acceptance; a compiler refusal or host timeout is not a passing negative control. The region datagram39-record regression also passes with its previous source graph and native artifacts unchanged.

Evidence: `docs/evidence/kekkai-native-udp-link-20261102/receipt.json`. Reproduce with `scripts/check-kekkai-region-os.py --component udp-link` and the pinned compiler/packager/baseline-lock/public-payload/QEMU/firmware arguments in that receipt. `--mutation udp-ip-checksum`, `udp-checksum` or `udp-fragment` selects a control. The standard cryptographic component paths remain separate. Native Amu emits executable/media formats; Python stages, hashes, constructs independent public wire bytes and observes the NIC peer.

No physical image, PXE reservation, Mac management service or production route was changed. The logical65535-byte cryptographic envelope is retained in its owner and is not relabeled as a single UDP payload at this MTU. Remaining integration includes Kekkai outer/inner framing, the crypto consumer's full app/desktop import closure, sockets exposed through admitted app operations, trusted clock/entropy/roster/revoke, Mac/OS app installation, actual authenticated round trips/reconnect, native SSH and production release. This link proof does not close those gates.

Status-note drift found while inspecting existing sources: `native/rtl8168_debug.kotoba:5` still describes its first stage as TX-only although `:272` implements RX. `native/desktop.kotoba:2127` says no entropy instruction is available although `:2141` calls `kernel-rdrand`. Existing history/comments were not silently rewritten; actual code is used, and neither mechanism is qualified for Kekkai merely by its presence.
