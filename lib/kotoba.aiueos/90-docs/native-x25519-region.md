# Existing OS X25519 under the current native ABI — JUN-757

The existing `os/aiueos/kotoba/x25519.kotoba` is an allocation-free RFC7748 implementation with an eight-argument entry: scalar/length, point/length, output/length and workspace/length. This work calls that exact canonical source without rewriting its arithmetic or changing its ABI. `os/aiueos/native/x25519_region_gate.kotoba` is a CPU-only public fixture; `scripts/check-kekkai-region-os.py --component x25519` stages, compiles and boots it.

Inputs and output are32 bytes each, with a separate646-byte workspace. The raw entry narrows each provided region with `kernel-subregion`; a short allocation traps. It is not a general shape/alias-safe API. The caller must supply valid disjoint buffers, preserve input immutability and wipe the workspace after secret use. An all-zero result returns0 and leaves32 zero output bytes; other results return1. A Kekkai caller must check that result before using a shared secret. This is distinct from the AEAD API's no-output-on-authentication-failure contract. Machine-code constant-time behavior, nonce/key lifecycle, application approval and authenticated real-peer operation remain separate qualification work.

The receipt at `docs/evidence/kekkai-native-x25519-20261102/receipt.json` records normal QEMU execution of528 cases: ten RFC7748 known answers/derived cases and the entire518-case vendored Wycheproof X25519 computation corpus. The extras cover both section5.2 vectors, Alice/Bob public keys and both directions of the shared secret, one iteration, ignored coordinate high bit, zero and order-eight points. Every full32-byte result and every return code is independently read back. Native checks also compare all input bytes and canaries after each call. The expected arithmetic output comes from the public corpus/RFC and is cross-checked by the existing independent Python reference before packaging. The raw API applies the all-zero contributory refusal to33 cases; this is an explicit policy, not an inference from a corpus label such as acceptable. The1000-iteration RFC stress sequence and secret-dependent machine-code timing are not qualified by this receipt.

The source-locked14-module kernel retains the actual ValueRuntime exports and two PT_LOAD segments. Kernel, EFI and diagnostic user-v5 ELF/slot are natively reproduced; user code is not executed. The existing256KiB domain request region contains output and return-code logs. The existing public font's zero tail at offset393216 holds67648 bytes of public vector data; header, glyphs and firmware prefix remain byte-identical. A nonzero/undersized tail refuses instead of overwriting another artifact. No code limit, memory grant, kernel/image admission or production deployment is relaxed. Python prepares public data, stages/hashes and observes; native Amu emits ELF/EFI and Kotoba emits GPT/FAT/ISO. The guest computes the actual X25519 outputs.

Seven separately compiled and booted mutations target scalar clamping, the required point bit254 mask, a24, conditional swap, inversion exponent, canonical reduction and the all-zero return policy. Their receipts preserve complete output/return mismatch indices and successful input/canary/completion controls. An initial high-bit-mask mutation (127→255) is semantically equivalent here: decoding into17 limbs of15 bits independently discards coordinate bit255. Its full528-case unchanged result is retained as an equivalent control, not counted as a detected fault. The final point-mask mutation (127→63) instead removes required bit254. The observer changed only this mutation definition after the earlier controls; the receipts preserve both observer pins and byte-identical positive native artifacts across that harness revision. The extended observer separately reruns the303-case hash/HMAC and1051-case ChaChaPoly gates. Initial prototype failures are retained as failures: an over-wide byte-store primitive trapped before X25519; replacing the font header with vector data failed native EFI admission; a later over-wide return-log store halted after producing the correct first shared secret. The corrected fixture uses appropriately narrowed byte/word windows and preserves the font header. A live stalled test was explicitly interrupted to save guest state before the correction; it was not classified as stopped from a polling timeout.

To reproduce, invoke `scripts/check-kekkai-region-os.py --component x25519` with the pinned compiler, packager, Amu source, baseline source-lock/public payload, QEMU and firmware in the receipt. Use `--mutation x25519-clamp` (or point-mask/a24/swap/invert/freeze/contributory) for the controls. The execution deadline defaults to3600 seconds; guest progress and captured failure context are retained. NICs and physical deployment are disabled.

Old source comments at `x25519.kotoba:64` and `:531` still describe a missing length parameter/four-argument entry. Actual code at `:535` uses eight arguments and checked subregions. This contradiction was reported in Linear; the existing header was not silently rewritten. This evidence qualifies execution of the existing region arithmetic, not the old C build-status narrative. The next step is IK/datagram state integration with the region hash/AEAD APIs, then signed netmap/socket/clock/key/revoke integration and actual Mac/OS app operation.
