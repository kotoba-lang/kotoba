# Shared AEAD import profile and bounded byte positions — JUN-757

The full `chacha20.region` facade retains its12 public APIs and512-byte state. Its arithmetic now lives once in `chacha20.region-ops`; the AEAD processing lives in `chacha20.aead-region`. The OS compiler checks all loaded functions, including unused raw entry points. IK imports the AEAD surface without loading unrelated raw block/Poly wrappers. The37 shared arithmetic functions are textually unchanged apart from visibility. Existing vector APIs are unchanged.

The AEAD profile additionally exposes `set-offsets(state,length,input-offset,output-offset)`. `set-length` resets both positions to0. Positions0..65536 are permitted, but seal/open check the complete position+logical length against the actual supplied buffer capacity before mutation. Results exclude the position. State fields468/472 hold input/output positions;476 is private MAC scratch. Physical state/input/output alias refusal remains. Authentication reads all16 tag bytes before any plaintext write. A refused setter or invalid shape preserves state; bad authentication consumes private AEAD state but leaves output untouched.

This avoids borrowing a memory view whose extent depends on a loaded protocol prefix. It does not mint a pointer or enlarge a buffer/grant. IK uses output/input positions80 and32; a datagram adapter can use8 with the same checked actual-capacity contract. The original facade operates at default positions0, with the same keys/nonces/frames and phase/length/wipe behavior as before.

The receipt `docs/evidence/os-region-20261102/profile-offsets.json` preserves1051 independent full-frame hash comparisons, existing guards and new position tests for both12- and24-byte nonces: shifted input33/output257, shifted decrypt output1111, whole64KiB output preservation on bad authentication, invalid/short setters, overflowing seal/open positions, empty input at the exact buffer end, a16-byte tag ending at byte65535, authenticated empty output at the buffer end and position reset by set-length. Nine normal-completion faults cover the previous seven cases plus ignored input/output positions. The two new faults leave legacy frame hashes unchanged and are detected by the new native assertions. They are not counted from a compile failure or missing completion marker.

The17-module compatibility kernel reproduces ELF/EFI and retains the actual ValueRuntime exports, two PT_LOAD segments,2MiB code cap and existing memory grants. The separate IK gate executes the AEAD-only import, complete maximum-sized handshake frames and post-handshake ciphertext vectors. Python supplies independent public expected data; native Amu/Kotoba emit all executable/media formats. This is not a machine-code constant-time, app/network, physical or production qualification.
