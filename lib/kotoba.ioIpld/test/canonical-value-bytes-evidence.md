# AWAI-531 canonical value wire check, 2026-11-14 JST

`kotoba.value.codec/verify-value-cid` documents canonical decoding, but the previous `ipld.value/decode-value` only decoded CBOR and validated the resulting form. The non-shortest encodings `82 18 00 f6` and `98 02 00 f6` decode as the same nil value as canonical `82 00 f6`; passing the actual CID of either noncanonical byte sequence was accepted. This contradicted the codec's documented canonical-byte contract. The source now re-encodes the decoded value and compares unsigned bytes, rejecting different encodings as `:value/non-canonical-bytes`.

On macOS, the local JVM oracle used Clojure CLI 1.12.5.1654; the local ClojureScript oracle used 1.11.132 and Node v26.0.0. Each ran the existing `ipld.value-test` and `kotoba.value.value-cid-test` plus `ipld.canonical-value-bytes-test`. The JVM passed 26 tests / 166 assertions; ClojureScript passed 26 / 167. The unmodified pre-change value source ran against the new regression and produced exactly four failures / zero errors, proving both noncanonical bytes were accepted by both `decode-value` and `verify-value-cid` with their own actual CIDs. Existing `.cljk` sources were copied as `.cljc`, unquoted `:kotoba/export` ns metadata quoted in the copies; the JVM-only copy of the existing tests maps `kotoba.test` to `clojure.test`. No downloaded dependencies or production fallbacks were introduced.

This closes the observed byte-canonicality error in the shared source. It does not establish a Native artifact or structural resource bounds for hostile recursive inputs. A byte-for-byte re-encode is performed per decode; its production performance has not been measured. Native and exact-head CI remain separate.
