# Where the ACVP vectors come from

The files under `test/mlkem/acvp/` are generated by `tools/import_acvp.py` from the
NIST Automated Cryptographic Validation Protocol (ACVP) server's published ML-KEM
(FIPS 203) vector sets. They are data; nothing in them is executed.

| Vector set | File | Bytes | SHA-256 |
|---|---|---|---|
| ML-KEM keyGen, FIPS203 (`vsId` 42) | `gen-val/json-files/ML-KEM-keyGen-FIPS203/internalProjection.json` | 558,841 | `d7a62a2c3476957f56dd8d24f9004ea6776ccfe995ffe71a65bb9506dc9c7b1b` |
| ML-KEM encapDecap, FIPS203 (`isSample` true) | `gen-val/json-files/ML-KEM-encapDecap-FIPS203/internalProjection.json` | 1,465,634 | `a556952ce869bb89c3a3196a701dad89647c193a34c86eafb61a9d710d5b810f` |

Repository: https://github.com/usnistgov/ACVP-Server (file URLs
`https://raw.githubusercontent.com/usnistgov/ACVP-Server/master/gen-val/json-files/...`).
Downloaded 2026-10-23 from `master`; the repository's `master` was
`975de31eb83d87039ec88934fdc47d8c312b892d` when this was written. The SHA-256 above
identifies the exact bytes that were used. They were read as text only.

`internalProjection.json` carries each test's inputs together with its expected
outputs. All groups of the `ML-KEM-768` parameter set are kept, and every test of those
groups:

| Group | Tests | What it exercises |
|---|---|---|
| keyGen AFT | 25 | `d`, `z` -> `ek`, `dk` (FIPS 203 Algorithm 16) |
| encapDecap AFT, encapsulation | 25 | `ek`, `m` -> `c`, `k` (Algorithm 17) |
| encapDecap VAL, decapsulation | 10 | `dk`, `c` -> `k`. Four of the ten are `modified ciphertext`: the expected key is the implicit-rejection key `J(z \|\| c)` (Algorithm 18). |
| encapDecap VAL, decapsulationKeyCheck | 10 | `dk` -> pass/fail. The failures are `modified H`: the hash check of section 7.3. |
| encapDecap VAL, encapsulationKeyCheck | 10 | `ek` -> pass/fail. The failures are `noisy linear system values too large`: the modulus check of section 7.2. |

ML-KEM-512 and ML-KEM-1024 are not implemented and their groups are dropped.

## Regenerate

```sh
python3 -I tools/import_acvp.py <keyGen internalProjection.json> <encapDecap internalProjection.json> test/mlkem/acvp
```

## Independent confirmation

Besides ACVP, `tools/openssl_interop.py` checks the library against OpenSSL's ML-KEM-768
with throwaway keys: key generation from OpenSSL's seed, decapsulation of OpenSSL's
ciphertexts, the implicit-rejection key for a modified ciphertext, and OpenSSL's
decapsulation of this library's ciphertexts. Last run (2026-10-23): 3 keys, all agree.
