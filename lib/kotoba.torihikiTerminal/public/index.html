What you are looking at

Every number on this page comes from torihiki, an open reimplementation of the exchange state machine that Hyperliquid keeps closed, running on ordinary torihiki nodes — plain processes on any host. The page reads several of them, compares what they say, and proves this session's balance against a state root more than two thirds of the validator set signed: prices are integer ticks, matching is price-time priority, and the roots are SHA-256 over a canonical encoding.

It is a devnet run by one operator, not a decentralized exchange. The page reads a four-replica BFT validator set, and all four keys are held by the same party, so a quorum of them is one party's word. Collateral is a faucet grant and nothing can be withdrawn to another chain. The node says which of these it is in its own /head response, and the Chain panel shows that answer. What it cannot do is lie undetectably — every block can be replayed against the same engine and its state root contradicted. What has to happen before any of this changes is in the decentralization roadmap.

This page renders with the same pure functions that render it on the server, so the browser and the node never disagree about what a row looks like. When the node is unreachable it says so above rather than freezing on the last good frame — a terminal that silently shows stale prices invites a trade.

604 ms per block

Measured on this deployment: 1.66 blocks/sec, and 2.6 seconds from submitting an order to seeing it. Hyperliquid publishes a median around 0.07 s, so this is roughly forty times slower end to end.

Engine: not what we claimed

This panel used to read "3,155,313 ops/sec — 15.8x HyperCore". That number does not reproduce: the same benchmark on the same code measured 5,639 and 25,314 ops/sec on two runs of a loaded machine. Until it is measured somewhere quiet, the claim is withdrawn rather than restated with a smaller number.

One operator, not consensus

Four replicas vote, and one party holds all four keys. Every decentralization flag the node serves is false until its gate passes in production. The log is checkable by replay, which is a different guarantee from tamper-evidence and the stronger one.

Signed, replay-proof

Every transaction carries an Ed25519 signature over the chain id, the account, a strictly sequential nonce and every field. Reusing a nonce is refused; signing someone else's account is refused.

No floating point

Every value is an integer inside the range both the JVM and JS represent exactly, so two validators cannot disagree in the last bit.
