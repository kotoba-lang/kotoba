# okaimono — 注文・明細・ライフサイクル（純粋データ契約）

**Status: R2**

`cloud-itonami-isic-5320`（コミュニティ・ラストマイル配送）向けの capability
library。`omise`（店舗）と対になる注文側。ネットワーク・I/O なし。

## 成熟度の梯子（この repo における R-tier の意味）

| tier | 意味 | 現在地 |
|---|---|---|
| R0 | 契約のスケッチのみ | — |
| R1 | 純粋な契約 + テスト | — |
| **R2** | **ドメイン契約が一通り揃い、test / lint / CI が緑。git 座標で消費可能。ただし本番の消費者で実証されていない** | **← いまここ** |
| R3 | 実際の消費者が本番でこれを叩いている | 未達 |
| R4 | 本番負荷で実証され、運用記録がある | 未達 |
| R5 | API が安定し、非互換変更に廃止手順がある | 未達 |

**R3 に上がるための不足**: 5320 actor が本番でこの契約を叩いている記録が無い。
加えて**注文に時刻が入っていない**（`placed-at` が無い）ので、SLA も滞留時間も
このデータからは計算できない —— 配送オペレーションの台帳としては、そこが次の穴。

## 触るときの注意

- **遷移表が唯一の権威**。`advance` は許されない遷移に対して例外ではなく nil を
  返す（拒否であって異常ではない）。`:handed-over` から `:cancelled` へは
  行けない —— 荷物は既に配送員の手にある。
- **`dispatchable?` は `:packed` のみ**。governor が配送を出す前に訊く唯一の質問で、
  ここを緩めると「まだ棚にある注文」を配送に出せてしまう。
- **`export/json-str` は U+0020 未満を全てエスケープする**（RFC 8259）。旧実装は
  制御文字を生のまま出していた。決済監査に流す台帳がパース不能になるので、
  これは体裁の問題ではなく監査証跡の破損。
- **`orders->csv` / `orders->json` は customer 列を持たない。** 顧客名の
  エスケープを検証したいなら、実際に出力される列（`:okaimono/store` など）で
  試すこと —— 出力されない値でテストしても何も検証していない。
