# ADR 0001: tilemap domain logic is sovereign Kotoba

`src/tilemap.kotoba` is the sole production language source. JVM Clojure is a
compiler/test host only.

Layers retain arbitrary positive logical width and height while storing at most
32 occupied tiles as a bounded sparse document vector. A tile cleared to empty
is removed persistently, so capacity is recoverable. Tilemaps allow at most 32
layers and generated instance batches at most 32 occupied tiles per layer.
Invalid dimensions, tile sizes, indices, and resource excess fail closed.

Collision, coordinate conversion, sparse layer updates, and deterministic
instance-data generation belong to Kotoba. Rendering, atlas upload, WebGPU, and
device execution remain capability-gated Kami providers.

Conformance is observable semantic, typed-ABI, resource, and rejection parity
across reference execution, restricted JavaScript, and instantiated typed Wasm.
Generated byte identity is not required.


## Amendment — 2026-08-13: authority and load path are different things

The migration that this ADR records deleted `src/tilemap.cljk` and left only
`src/tilemap.kotoba`. A `.kotoba` file is on no Clojure classpath, so from that
commit onward `tilemap` could not be loaded by ANY runtime this workspace
ranks above the native path (`kotoba wasm` > `clojurewasm` > ClojureScript > nbb,
and the JVM below them). "Production `.clj`/`.cljc`/`.cljs` sources are forbidden"
was read as "delete the load path", and the two are not the same requirement.

`src/tilemap.cljk` is restored beside the `.kotoba`, and:

* **the `.kotoba` remains the sole semantic authority.** Nothing about the migration
  is reverted. The restored file is a load path, not a second design.
* **a parity gate holds the two equal.** `test/tilemap_parity_test.cljk` compiles the
  `.kotoba` here and runs it through the reference evaluator in the same JVM,
  asserting agreement value by value. Where agreement is impossible it says so in a
  named test rather than dropping the case from the comparison.
* **`kotoba-lang/compiler` moved from `:deps` to the `:test` alias.** A consumer that
  requires the `.cljc` must not drag a compiler in behind it. `kotoba-lang/css`,
  `/dsl-core`, `/async` and `/postfx` set the same boundary.
* **`production-source-authority` is narrowed, not deleted.** `src/` is exactly two
  files. A third file, or a second `.cljc`, is still a fork of the authority and
  still fails.

**Semantics: behaviour restored verbatim, validation taken from the guest.** The
restored file is `2ce204c3^` unchanged except that `tile-layer` and `tilemap` now fail
closed on non-positive dimensions, because the guest traps there and ADR-2608130900
set that precedent in `kotoba-lang/async` (the guest's `chan` validated where the
original did not; the restored `.cljc` adopted the validation).

Parity here is asserted over BEHAVIOUR, not over state, and three divergences are
named:

1. **Storage.** A KIR document container holds at most 32 items, so a dense `w*h` tile
   vector is impossible in the guest for anything larger than a 5x6 — this repo's own
   test builds a 10x10, which would need 100. The guest therefore stores `:tiles`
   sparsely as `{:x :y :tile}` entries. This namespace keeps the dense vector the
   pre-migration contract published; it has no 32-item budget, so rewriting it to the
   sparse shape would change its public value for nothing.
2. **`layer-to-instances` order.** This namespace walks the grid row-major; the guest
   walks its sparse entry list, i.e. insertion order. The contents always agree; the
   sequences agree only when tiles were set row-major. Both cases are asserted.
3. **The 32-item bound bites at the 33rd occupied tile.** For a tilemap that is a
   small room, not an exotic edge, so it is recorded as a narrowing of the contract.

**Removal condition.** The `.cljc` comes out when consumers have a load path that does
not require it — for the native route, ADR-2607279200 W4 in `com-junkawasaki/root`.
Until then, removing it is not a step of the migration; it is an outage.

Recorded in `com-junkawasaki/root` as ADR-2608134800, which follows ADR-2608130900
(`dsl-core`, `async`) and ADR-2608133600 (`postfx`, `cartpole-math`).
