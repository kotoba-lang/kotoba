# Native Kekkai interoperability (JUN-757)

Kekkai's existing node calls `noise/suite` without a hash override. Its suite is
`Noise_IK_25519_ChaChaPoly_BLAKE2s`. The previous native implementation supported
SHA256 suites only, so the presence of native X25519 and ChaChaPoly did not make
it compatible with that node.

`noise.native/initialize` pattern **4** now selects that exact IK/BLAKE2s suite.
Patterns 0–3 retain their existing meanings. `noise.blake2s-native` implements
unkeyed BLAKE2s-256 and HMAC-BLAKE2s, including long HMAC keys. Noise HKDF uses
HMAC, not BLAKE2 keyed mode. This is a native Kotoba implementation: no host
crypto call or legacy CLJK runtime executes in the guest.

The `noise` module gate now includes both sides of the published Cacophony
IK/BLAKE2s vector, in addition to the six existing SHA256 groups. Each checks
handshake bytes, transcript hash, transport bytes, tampered ciphertext and
out-of-turn refusal. HKDF, es/se and IK pre-message mutations must be detected.
The separate `blake2s` gate checks the RFC 7693 `abc` digest, empty input,
a corpus of lengths 0–257, HMAC key lengths 0/32/64/65/100, and non-byte refusal.
The corpus's public expected values are generated by independent Python
hashlib/HMAC; assertions execute in the native image. Rotation, final-block and
long-key mutations must be detected.

Run `scripts/check-pq-native.py --gates blake2s,noise,datagram` with explicitly pinned
native compiler and packager paths/digests and a fresh output directory.
Public test keys only; no device identity is enrolled or copied by these gates.

`noise.datagram` now implements the existing node's transport wire format:
8-byte little-endian counter followed by ChaChaPoly ciphertext, with the header
as associated data. Its circular 2048-counter window accepts reordered frames;
only authenticated frames change state. It requests rekey after 120 seconds
and rejects after 180 seconds, on backwards clocks, or on exhausted counters.
Construction requires a completed IK/BLAKE2s handshake and an exact match with
the roster-provided expected peer key. The caller must consume a fresh handshake
once, retain the returned current session state, supply a monotonic clock and
close sessions when their signed policy is revoked or replaced. This pure core
does not authenticate a netmap or provide a grant.

The native datagram gate returns 255. It checks a public independent Python
reference's exact wire bytes (that reference first matches Cacophony's complete
IK/BLAKE2s handshake), bidirectional data, empty authenticated payloads,
reordering, replay/window limits, tamper/header/length refusals, peer binding,
clock/rekey/expiry, counter limits and unchanged input states. Replay, window,
expiry, omitted associated data and peer-binding mutations return respectively
251, 251, 239, 254 and 223. They are detected guest assertions, not compiler
crashes. The first observer attempt stopped because its mutation pattern was
not unique; the corrected second attempt passed all controls.

This closes cryptographic and pure datagram prerequisites, not installation or
live connection. Signed-netmap consumption, socket integration, application
entry, per-operation consent and physical Mac–6600H roundtrip remain separate
work. This classical suite also does not satisfy the newer post-quantum broker
transport contract.

The existing 6600H kernel profile cannot yet import this shared closure. A locked
compile probe retaining the actual ValueRuntime root reaches `sha2.core/s2-k`
and is refused by the pinned compiler: `E7102`, detail 4, unsupported object
profile or code limit (`frame=640 kind=2 n=0 rt=4 sir=38`). This is a measured
refusal of the current closure/profile, not proof that every native target is
incapable. A region-based kernel port or a separately qualified user runtime
is needed before deploying these modules as an OS application. The probe has
not booted or changed the physical machine. `scripts/check-kekkai-os-profile.py`
reproduces and records that refusal against an explicit baseline source-lock
pin; a refusal exits 2 and cannot count as a passing OS gate.

Documentation discrepancy found during this task: the older README's first
native-port paragraph says state size 362; current `noise.native/state-size` is
1646 after the XXhfs extension. The source layout is authoritative. The README
is retained pending owner decision rather than silently rewriting its history.

Specifications: [RFC 7693](https://www.rfc-editor.org/rfc/rfc7693.html) and
[Noise revision 34](https://noiseprotocol.org/noise.html).
