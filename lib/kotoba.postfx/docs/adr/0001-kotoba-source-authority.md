# ADR 0001: post-effect configuration is sovereign Kotoba

`src/postfx.kotoba` is the sole production language source. It retains all
effect constructors, pipeline composition, curated presets, and uniform-layout
configuration as canonical bounded documents. JVM Clojure is a compiler/test
host only.

Each pipeline is capped by the canonical document-vector budget of 32 effects.
Host objects are not accepted as configuration, and persistent updates cannot
mutate caller-owned data.

This package describes passes only. Shader execution, uniform upload, WebGPU,
render-pass scheduling, and device access remain explicit Kami providers.

Reference execution, restricted JavaScript, and instantiated typed Wasm must
agree on observable values, typed ABI, effects, bounds, and rejection behavior.
Generated byte identity is not required.

## Amendment 2026-08-13 — authority and load path are separated

`src/postfx.kotoba` remains the sole SEMANTIC authority. It is not reverted and no
decision above is withdrawn.

What is corrected is a conflation. "Sole production language source" was read as
"sole file under `src/`", and on 2026-07-20 `15c7fda2` acted on that reading by
deleting `src/postfx.cljk`. That did not move the `postfx` namespace to Kotoba for
its consumers — it removed the only way any Clojure runtime (JVM, nbb,
ClojureScript) can load it at all. `kotoba-lang/kami-postfx-scene` requires
`[postfx :as postfx]` from `src/postfx_scene.cljc:61`, on its production path. It
kept building only because its `deps.edn` pinned this repo at `876fe9de`, four
commits before the migration; anyone advancing that pin would have broken it.

So:

* `src/postfx.kotoba` — the semantic authority. Reference execution, restricted
  JavaScript and typed Wasm must agree on observable values, typed ABI, effects,
  bounds and rejection behaviour, exactly as stated above.
* `src/postfx.cljk` — the LOAD PATH. Held to the authority by
  `test/postfx_parity_test.cljk`, which compiles the `.kotoba` and runs it through
  the KIR interpreter in the same JVM and compares typed documents. This is the
  shape `kotoba-lang/css`, `kotoba-lang/dsl-core` and `kotoba-lang/async` use
  (ADR-2608130900 in com-junkawasaki/root).

`production-source-authority` in `test/postfx_test.cljk` is NARROWED, not deleted:
`src/` is exactly these two files. A third file, or a second `.cljc`, is a fork of
the authority with nothing asserting agreement, and is still refused.

`kotoba-lang/compiler` moves from `:deps` to the `:test` alias. Consumers require
the `.cljc` and must not be made to drag a compiler in behind it.

Two differences from the guest are stated rather than papered over, and both are
asserted by the parity test:

* `effect-types` is a `def`'d set in the `.cljc` and a nullary function in the
  guest, because Kotoba has no top-level value bindings. Membership is identical.
* A pipeline is a KIR document-vector, capped at 32 items. The `.cljc` has no cap.
  The parity test asserts agreement at 32 and asserts the divergence at 33.
  Narrowing the `.cljc` to 32 would be a promise this library never made; the
  largest shipped preset is `final-fantasy` at 10.

REMOVAL CONDITION for `src/postfx.cljk`: when consumers have a load path that does
not require a `.cljc` — for the native route, ADR-2607279200 W4. Until then,
deleting it is not a step of the migration, it is an outage.
