# Native FS2 write and read of Forest files, 2026-11-14

A macOS arm64 Native executable opened the two actual random Forest files described in `native-random-2pack-evidence.md`, read each in at most 262,144-byte FS2 E calls, and wrote the bytes into new scoped output files using FS2 B then C. A separate Native executable searched the resulting two files and verified the canonical manifest, every chunk CID/length and the whole 17 MiB logical SHA-256. The shell checked the copied archive lengths and SHA-256 against the source pins, and renamed the completed test files into the reader's expected fixture directory; it did not write the copied archive contents. Positive copy/read exits were 0/0. Corrupted and missing second-Pack controls each exited 11. The unmodified input and all experiment outputs remain preserved.

`native_forest_copy_gate.sh PINNED_AMU EXTRACTED_INPUT NEW_OUTPUT` checks the signed compiler/packager pins and input digests, uses source locks, compiles two Native programs and invokes no host block decoder. Fresh `.agent-output/native-forest-copy-04` had copy executable SHA-256 `edb19525e1097a4c8c008b9e89e8e8605151ebbe7928e6950ece1629342cec4f`, copy source-lock SHA-256 `55820ebdfaaed3019134108118a61d5ccece94b47e29131a3b27c59f602b051b`, reader executable SHA-256 `38af499f3e09ff715c43639360d62662b4722f087bd9a3e623af46a83e5a4731`.

An initial copy attempt trapped (133) on the B request using a path containing `/`. Separate one-byte Native controls showed E read exit 0, B with `/out` trap 133, and B with basename `out` exit 0. The pinned macOS packager's B/C implementation documents scoped no-symlink basenames; the successful copy uses those names. Invalid operations can trap rather than return a recoverable error.

This is Native copying and reading already-encoded Forest files, not a Native Forest encoder, index creator, catalog transaction, atomic publication, explicit fsync, crash/reboot/OS-cache-loss test, authenticated catalog, concurrent-truncation guarantee or independent node. The copy overwrites its basename if it exists, so the gate requires a new private output directory; it is not a safe general file-import interface. Host orchestration, data source, file movement and test key/artifact pins do not qualify a production release.
