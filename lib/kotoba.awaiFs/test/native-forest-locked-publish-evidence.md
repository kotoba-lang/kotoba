# Native cooperative Forest writer lock, 2026-11-14

`forest-locked-publish/publish` acquires the pinned Linux Native provider's nonblocking scoped flock at `parent/.awai-writer.lock`, invokes the CID-checked publisher, and releases the lock on a normal return. Status 104 means the lock was not acquired and no staging was attempted; status 102 means unlock was not acknowledged and publication state must be inspected. A process trap can bypass the explicit unlock, though process exit releases the kernel flock. The lock file must remain at one stable inode, and every writer must voluntarily use the same path and protocol. This API does not implement distributed epoch fencing or protect against a same-identity actor replacing the lock file or changing staging and published data through another route.

On the dedicated Ubuntu 26.10 Linux aarch64 guest, two independent Native processes started against the same parent and a 16,777,219-byte / two-Pack source and trusted test manifest CID. Exactly one returned 0 and one returned 104; the busy caller created no staging directory, and the successful generation's Pack and manifest bytes matched the previously checked generation. The lock file remained mode 0600 with one link. Native artifact SHA-256 `54f4c0decffe677802a9b45e1401894f5c163d4d6cee901ab7c56ee18ca291a6`; guest-specific KSL1 lock `5a166defd024d5405150cf85af9d09217e5755bb48efae4da66cad6cb727ddae`.

In a separate run, a child was SIGKILLed after its private staging directory appeared, while another writer returned 104. A fresh process then acquired the lock and returned 95 because the generation name already existed; its preexisting Pack and manifest hashes remained unchanged. A bad-CID publication returned 101, after which a fresh process again acquired the lock and reached the existing-name refusal. Interrupted and rejected private staging remains in the task-owned guest. The no-replace status by itself does not prove content equality or durability. Inputs and outputs are retained in `locked-publish-test` in that guest.

This local cooperative concurrency and process-death result is not a hostile-writer guarantee, distributed fencing, WAL/head recovery, cleanup proof, independent-node test, physical power-loss test, or production qualification. The external CID is not authenticated by this function.
