# Native private Forest staging, 2026-11-14

`forest-source-stage/stage-private` first checks the source's regular-file size, asks Linux Native FS2 N to create an exclusive randomized `awai-stage-` child under the supplied absolute parent, validates its framed returned path, then stages into that child. It returns a record containing the child path and stage status when control returns normally. The older `stage` remains a lower-level entry requiring an already exclusive empty prefix and can overwrite its contents.

In a dedicated Ubuntu 26.10 aarch64 guest, the pinned Native compiler compiled `native_forest_private_stage_smoke.kotoba` under a source lock. A size-mismatch call returned status 2 without creating a child. Two sequential successful one-byte calls produced two distinct mode-0700 child directories; an existing sibling sentinel stayed unchanged. Two processes ran the same program concurrently, each performing two successful calls. Both returned Native result 0, and six distinct child directories existed in total with the sentinel intact. One staged result was imported into an independent Babashka/Otehon store and its single recovered byte matched the source `Z`. Native artifact SHA-256 `02e163134a2696109591b0b91cb237280cffed0220b35f144f5e5bdc712cc4f4`; guest-specific source lock `5b6a232dc68223475d06cb53c6e27d2141afb02b02ac374b8ea551431457ab7a`. Outputs and the oracle store remain in task-owned evidence locations.

FS2 N is an unmanaged exclusive mkdir, not the managed transaction protocol. Interruptions, provider traps, invalid returned paths, or stage failure may leave an orphan; a provider trap cannot return its path to the caller. The randomized child does not exclude another process running as the same identity from inspecting or modifying it. Input changes after the preflight, source replacement, cleanup, fsync ordering, WAL, writer fencing and atomic root publication remain open. This narrow local test is not a production durability, hostile-concurrency or cross-platform qualification.
