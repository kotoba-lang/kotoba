# Native 1 MiB Forest Pack construction, 2026-11-14

The existing `ipld.car.pack` and `awai.fs.forest-write` 64 KiB APIs keep their limits and behavior. New explicit `encode-large` and `root-cid-large` CAR APIs use a bounded 1,049,600-byte CAR profile; `forest-write/encode-large` composes those with Native raw/RLE Zstd frames and the existing Forest index writer. This supports a 1 MiB leaf, without changing canonical bytes or silently changing the existing logical chunk profile. It builds one complete Pack in memory; it is not a streaming GiB or multi-Pack transaction.

On macOS arm64, `native_forest_large_write_gate.sh PINNED_AMU NEW_OUTPUT` used pinned signed Native compiler/packager with KSL1 source locks. Native produced a 1,048,576-byte deterministic nonuniform leaf, confirmed the old bounded API refused it, constructed its Forest Pack, then wrote the file via scoped FS2 B/C pieces of at most 262,144 bytes. A separately compiled and separately started Native reader used FS2 positioned reads to verify the leaf CID and every byte. A damaged footer was refused. The resulting Forest file is 1,048,913 bytes; SHA-256 `f0c0ce3b46c3dadde6f30e4841cd1849dca9ed884cdff7ede2cab3d716e6bf1f`. Source locks: writer `8a2e7657d78b75c0b4a3337e74714b40173e628492c45c6cf4eac0a86fcab342`, reader `90f291ca603807b2eb30782accd71e7eb7ab227a1fa899e23cd11285adcd9f9d`.

A separate one-time Babashka 1.12.218 Otehon `forest/verify-file` oracle validated the full archive, canonical CAR header, Pack root, index and block digest. The independently generated expected leaf SHA-256 matched `8d669c1dc75bfdf5116eb563ac87942c82d9a15b5c8992d10c05be268e4cd67a`; root CID `bafyreifgtl3oln7o73tvhgh7wm5sxnuytsb7hwizzm7f2rw36gmns44aoy`. This oracle was not in the Native gate or a fallback. The earlier 64 KiB Native gate was rerun: all three generated archives were byte-identical to the pre-change outputs. Evidence is retained under `.agent-output/native-large-forest-03` and `.agent-output/native-forest-legacy-regression-01`.

This is a local Native encoder/file I/O interoperability result, not GiB Native writing, bounded-allocation proof, compression-rate claim, multi-Pack atomicity, fsync, concurrent truncation safety, OS-cache-loss recovery, key admission, independent node or production qualification. FS2 B/C writes the test file and may trap on invalid paths.
