# Cooperative Native Forest HEAD transition, 2026-11-14

`forest-head/advance` stores a small `awai-head-v1` management record containing a generation name and logical manifest CID. Under the same stable scoped flock used by cooperative local writers, it compares the current HEAD with the caller-supplied expected old record, verifies the old generation when present, and verifies the proposed generation using `forest-generation-verify`. Initial creation uses Linux FS2 T / `RENAME_NOREPLACE`; an update uses FS2 L / `renameat` while the cooperative lock is held. The temporary HEAD file and its private directory are synced before rename, and the temporary directory and parent afterward. The name/CID management record is not itself a content-addressed canonical form.

Statuses include 0 acknowledged, 104 lock busy, 105 stale or missing expected HEAD, 106 invalid old generation, 107 invalid proposed generation, 108 pre-commit or rename refusal (a malformed provider response requires inspection), 109 post-rename sync failure with potentially visible HEAD, and 102 unlock failure with uncertain outcome. An interrupted operation can leave a private temporary directory. Provider traps can exit without a status. This is a cooperative local compare-and-replace protocol, not a hostile-writer or distributed fencing guarantee. All writers must use the same stable lock inode and must not bypass the protocol.

In the dedicated Ubuntu 26.10 Linux aarch64 guest, the pinned Native compiler built `native_forest_head_smoke.kotoba`. Bootstrap and one update returned 0; attempts based on stale state returned 105. `strace` recorded exclusive flock, temp-file fsync, temp-directory fsync, no-replace rename for initialization or renameat for update, temp/parent fsync, and unlock. A separate status fixture returned 106 when the old generation's Pack was corrupted and 107 when the proposed generation's Pack was corrupted, with HEAD unchanged in both cases and test objects restored. Two concurrent updates from the same old HEAD returned 0 and 104; a later stale retry returned 105.
