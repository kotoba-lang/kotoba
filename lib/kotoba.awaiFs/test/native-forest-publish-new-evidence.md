# Native no-replace Forest generation publication, 2026-11-14

`forest-source-stage/publish-new` stages and syncs an explicitly sized source in a fresh private child, then uses Linux FS2 T (`renameat2(RENAME_NOREPLACE)`) to expose that directory under a caller-selected `gen-` name in the same parent, followed by parent fsync. It returns a stage-result record. Status 0 means the operation and final sync were acknowledged; 95 means rename returned false and the staging path is returned; 96 means rename succeeded but parent sync was refused, so the target may already be visible; 97 means a malformed response and publication state is unknown. Provider traps can terminate the process without a result. Existing targets are not replaced. The generated name is a caller-chosen location, not a CID or a mutable head.

On the dedicated Ubuntu 26.10 Linux aarch64 guest, the pinned Native compiler built `native_forest_publish_new_smoke.kotoba` with a 16,777,219-byte random-plus-suffix source. The Native result was 0, with two Forest Packs and one manifest. An `strace` recorded fsync of both Pack files, manifest, staging directory and parent, then `renameat2(..., RENAME_NOREPLACE)` and another parent fsync. Native artifact SHA-256 `a8a7f2d2b9135f44e3f530dfb5a382c044e50f3bc453bf7adf7e6cbb905cf795`, source lock `2e8636dd31bb77e9eeeb7b44ba8960152f54eb418fdbfc4e20e84aa95341e074` (lock paths are guest-specific).

A second execution returned 95 and trace showed `EEXIST`; the existing generation's Pack and manifest hashes and a sibling sentinel stayed unchanged. Two concurrent processes targeting a separate identical name produced one result 0 and one result 95; the winner's Pack and manifest bytes matched the first published generation. The rejected writer left a private staging directory. The invalid-name Native fixture checked empty, short, traversal, slash and uppercase names and created no objects.

After guest `sync`, clean shutdown and restart, boot ID changed from `c4e5844a-3137-4b2b-a830-c4938c5016b3` to `63fb0088-f187-41e2-a460-3ec7f74fb638`; published Pack and manifest hashes matched. An independent local Babashka/Otehon oracle imported the post-restart files and verified all 16,777,219 bytes against the source; manifest CID `bafyreifofrzrmfqc2affepxac6oyi57owuaulr3pvmqi2dftdtfmjtxifq`. In a separate source-mutated control, forcing the final sync check to fail returned 96 while the target was visible. This was branch simulation, not an actual storage error.

This is creation of a new immutable-named directory, not an update to an existing root pointer, a WAL transaction, source snapshot, signed basis, concurrent hostile-writer fencing, or production acceptance. Collision and process failure may leave orphans. A same-identity process can tamper with staging or published files. `fsync` and guest reboot do not prove a physical disk honored flushes or lost host caches. Inputs, traces and outputs are retained in the task-owned guest and `.agent-output/native-publish-evidence`; the hosted oracle is not a Native dependency or fallback.
