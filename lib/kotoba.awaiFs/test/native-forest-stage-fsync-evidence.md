# Native Forest staging fsync, 2026-11-14

The staging writer now calls the Linux Native FS2 M sync form for each completed Pack, then for the manifest and staging directory. `stage-private` then syncs the parent directory before reporting success. Each framed boolean is checked; a false or malformed response returns a failure status. A provider trap can terminate the process and leave staging files. No WAL or root publication is performed.

On the dedicated Ubuntu 26.10 aarch64 guest, a pinned Amu Native run of the private-stage smoke returned result 0. `strace -yy -e trace=fsync` recorded, twice, successful syscalls in this order: `pack-0`, `manifest`, the child staging directory, then its parent. The Native artifact SHA-256 was `87b1ac5154960cdbee393bf664ace28e7c1fe450a85e6090b73a02d82606f894`, the guest-specific source lock `a1310d7c00f7f4efae3c28ba3da7e0ad7a00227481b05c5d580cf1abbe9f5575`, and trace SHA-256 `27d6847a1525720fbc5da1ed895a07a807b05338072d3c2c680b91752905d9a1`. The variable-size Native smoke also passed for 0, 1, 1,048,579 and 16,777,219-byte inputs, with all output bytes equal to the preceding unsynced run.

As a control, a separate source-locked build replaced the sync helper with a function returning false: the caller returned failure and no manifest appeared after the Pack sync check. This control tests the branch, not an actual disk failure. An attempted `strace` EIO injection failed in this guest with SIGSYS and exit 120; it did not establish EIO handling. Trace files, binaries and control output are retained in the dedicated guest. Prior staging evidence describes the earlier implementation before these sync calls. These observations do not prove storage hardware honors flushes, power-loss safety, safe cleanup, source snapshots, fencing or atomic publication.
