# Native read of Otehon's actual 1 GiB writer output

On 2026-11-14 Darwin 25.4.0 arm64, this test read the manifest and 64 Forest Packs actually published by `network-awai/awai-os` draft PR #124 `gib_actual_writer.clj`: 1,073,741,824 logical bytes in 1,024 1 MiB chunks with unique markers and zeros elsewhere. The published manifest CID was `bafyreidk3dxbsrqaocvdhfr624j4n75v6ddgmyfgkyu24z3lirlg5aj4g4`; manifest bytes SHA-256 was `6ad8ee19460070aa33963ed713c6ffb5f0c66660a65629ae676b44566e813c37`. The expected full logical stream SHA-256 was independently measured by the Otehon writer/readback as `1f7e0c0d3fefe5579e556a04f7796b7de01278916e49a6d31df864e16adf1708`. The 64 ordered compressed Pack lengths and SHA-256s are in `actual-gib-packs.tsv` (file SHA-256 `5a08409737626a0ef1bb37f5d4264a1dbcdf5f94590d27872293d8a49c3590ba`).

The one-off `extract_otehon_actual_gib.clj` was run with Otehon's Babashka 1.12.218 classpath against the retained task-owned store, after its recovery and manifest validation. It copies the manifest and actual archive files; a second independent extraction matched every file byte-for-byte. This extraction is a hosted reference preparation, not Native, CI, a required production path or a fallback. The separately executed `native_actual_gib_gate.sh` uses shell orchestration, pinned signed Amu Native compiler/packager and KSL1 source lock, with no Python or host block decoder. It verifies all input pins, then Native opens actual files through its scoped FS2 provider, validates the logical manifest CID, reads all 1,024 chunk blocks, verifies each CID and length, and compares the complete streaming SHA-256.

The final full gate ran with positive exit 0, a staged one-byte corruption in Pack 31 exit 41, and the same Pack missing exit 41; stderr was empty in all three. Native source lock SHA-256 was `d21147dce9773bb6a63c834df47d7aeda5e090ba7b5e83d7158e2f91c209c209`; signed macOS executable SHA-256 was `44121b83b3a00544c893e2f62638bbfcd1ab7fa7736c60c460f7860dc99007c6`. Outputs and inputs remain under the originating worktree's `.agent-output`; original Otehon data were not changed. This is a local Native artifact result, not exact-head CI or Linux qualification. The old broader Python-based workflow remains a separate known policy issue and this new narrow shell gate does not claim to replace it.

The input is highly compressible synthetic data. Physical Pack locations/order, expected manifest CID and expected whole-stream digest are supplied as pinned test inputs; there is no authenticated catalog, Native writer, bounded concurrent mutation guarantee, OS cache-loss recovery, independent node or production qualification in this test. Host tool copies prepare inputs and orchestrate compilation only; Native makes the block/CID/hash verdicts.
