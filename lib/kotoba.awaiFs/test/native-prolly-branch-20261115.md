# Native bounded Prolly lookup, 2026-11-15

`awai.fs.prolly-tree/lookup` follows CID-verified Forest blocks for an exact key, with a 64-node bound. Internal nodes select the first child whose maximum key is at least the key, or the last child otherwise, matching the fixture's pinned Prolly source (`prolly_tree/core.cljc` SHA-256 `39f782fe4ba29cebf14f5437e7800713e89826e080fb7f8ab42b8123b33c4a30`). Branch keys are deliberately limited to ASCII, children to 4096, and CID links to the supported 36-byte sha2-256 CIDv1 raw/DAG-CBOR profile. Non-ASCII, unsorted children and malformed links are refused. This is exact lookup only; there is no prefix scan, full Datalog execution, root authentication, decryption or policy/receipt enforcement.

The macOS Native test reads the actual Otehon `spo` leaf through `prolly-tree/lookup`, checks its CID through the Forest read, finds the file key/value, and rejects an absent key. A separate synthetic two-child internal node tests the boundary, equality, next-child and last-child rules, then selects the real leaf CID, which the existing test fetches from FS2. Unsorted boundaries and malformed IPLD links are rejected. The synthetic internal node was passed as bytes to the selector; it was not persisted in a Forest pack, so a multi-level FS2 traversal is not yet proven. The real fixture itself has a leaf root and uses identity encryption and fixture blinding.
