# Native reader: actual random two-Pack Otehon output

On 2026-11-14 macOS arm64, the Native Forest reader opened the recovered output of the actual hosted Otehon `put-file-large!` crash test at awai-os PR #124 commit `cdb781f`. The file contains 17 MiB generated from `java.util.Random` seed 532 after a 1 MiB old file; its two persisted Forest files are 16,779,503 and 1,048,922 bytes. They were taken from the fresh recovered copy of the root-rename SIGKILL case, not generated by Native. This corpus complements the separately recorded highly compressible 1 GiB fixture; it is not a GiB random-file or throughput test.

One-time hosted oracle `extract_otehon_random_2pack.clj` used Babashka 1.12.218 and the Otehon source/vendor classpath to recover the store, verify its catalog and extract the canonical manifest and two Forest files. It is fixture preparation only, not part of Native execution or CI. The logical file SHA-256 is `0f040d1cc79d7489ae4c4f001c758f77092afeb7c886408a8c12c058c56048f1`, the manifest CID is `bafyreicujzf6yca5uiqg4vvzu4f4zjjjrgb2zk5v4clj7psmgpveugiskq`, and manifest SHA-256 is `544e4bec081da2206e56b9a70bcca5298983acabb5e0969fbe4c33ea4a191254`. Pack sizes and hashes are pinned in `actual-random-2pack.tsv`.

`native_random_2pack_gate.sh PINNED_AMU EXTRACTED_INPUT NEW_OUTPUT` checks pinned signed compiler and packager, input digests, and source lock, and builds/runs macOS Native code without a host block decoder. The Native program searches both Pack paths for each of 17 chunks, checks the manifest CID, each chunk CID and length, then the full streaming SHA-256. Local positive exit was 0; independent staged corruption and absence of Pack 1 each exited 11, before a successful full read could be reported. Source lock SHA-256 `2e0e3098733f256d72cc732458ac5c1bc03616abac2b70a1737000b9bb13fd0e`; signed executable SHA-256 `38af499f3e09ff715c43639360d62662b4722f087bd9a3e623af46a83e5a4731`. Inputs, program and results are retained in the task worktrees.

This verifies a selected-block reader on macOS with caller-supplied expected root and physical locations, not an authenticated catalog, Native writer, OS-cache loss, concurrent truncation safety, Linux parity or production qualification. The hosted writer's SIGKILL and the Native read are separate steps; this is not a Native OS reboot.
