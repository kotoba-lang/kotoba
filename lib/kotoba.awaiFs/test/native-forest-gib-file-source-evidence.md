# Native file-backed Forest GiB fixture, 2026-11-14

`native_forest_gib_source_write.kotoba` is a test-only adaptation of `native_forest_gib_stream_write.kotoba`: the test substitutes `SOURCE_INPUT_PATH` with a scoped absolute input path, and `block` reads four bounded 262144-byte pieces through `awai.fs.source-file/read-range`. For each 1 MiB leaf, the first read computes its CID and a second read is checked against that CID before the Forest frame is emitted. The fixed fixture still writes 64 Packs and one manifest; it is not a general input-size API or atomic publisher.

On the dedicated Ubuntu 26.10 aarch64 VZ guest, an independently created 1,073,741,824-byte sparse file with distinct two-byte leaf prefixes and zeros elsewhere had SHA-256 `f0add2045c361a831c9298f69c09e65a79c0c83d38bc97bc84bfe9b909dc5d77`. The pinned Amu Native compiler and provider from `native-inputs.json` compiled the path-substituted source under a KSL1 lock. Its writer returned `:status :ok :result 0`; all 64 output Pack SHA-256 values and the manifest bytes matched the previously verified Native generator, including manifest SHA-256 `71a79734dfdac0c0c910bc7786fbc579480150f1a5cdefebddb9c88c8c3d85a2`. Native binary SHA-256 `ae171624a3618c659b867a77f4acd6d56af753cd32a2cb23edab08d0509103e8`, guest-specific lock SHA-256 `80c2aa9c69fd6b888d8697d004fdb870eea2df40729e756005ae8d8365ac3494`. Guest output and input were retained.

For a separate source copy, the test waited for Pack 0 to be created, after its sixteen CIDs had been computed, and changed the first byte of leaf 15 before its second read. The writer returned result 10 and no manifest appeared. This is a single targeted mutation control, not a source snapshot or proof against concurrent changes outside this window. The provider can terminate the process on missing or truncated source; partial Pack files can remain. The fixture does not perform WAL, fsync, atomic root publication, writer fencing, or production policy admission. The input is synthetic and highly compressible, and no performance or physical power-loss claim follows.

A subsequent Linux Native run replaced the fixture's inline four-piece reads with the shared `source/read-chunk` implementation. It returned result 0, and the 64 Pack SHA-256 values and manifest bytes again matched the original generator. The new Native binary SHA-256 was `dbf1baf41b8a94fe4992ed3e2596f0b16d970e38bf36c6197f8cb74739240a5e` and the guest-specific KSL1 lock was `c8ae571e96a50f3e5c48d8c52e013420a431ca246435fcc52037b99bba03a113`. The earlier mutation control was performed on the prior inline-reader version, not repeated on this one.
