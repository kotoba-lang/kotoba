# Native 1 GiB Forest construction and readback, 2026-11-14

A synthetic Native test program constructs 64 Forest Packs with 16 distinct 1 MiB leaves per Pack, and a canonical logical-file v1 manifest: 1,024 leaves / 1,073,741,824 logical bytes. It computes each raw CID first, builds the canonical CAR root, then writes bounded Zstd raw/RLE frames and Forest index/footer through scoped FS2 B/C requests. A per-leaf arena scope avoids intentionally retaining the entire logical file. The deterministic fixture uses two varying prefix bytes per leaf followed by zeros; it is highly compressible. Each physical Pack is 2,098,986 bytes. This is an executable fixture that generates bytes, not a product source-file ingestion API or atomic multi-Pack publisher.

`native_forest_gib_stream_gate.sh PINNED_AMU NEW_OUTPUT` compiles the writer using pinned signed macOS arm64 Native compiler/packager and a KSL1 lock; it then invokes `native_forest_gib_stream_read_gate.sh` to compile and run a separate Native reader. On `.agent-output/native-gib-stream-author-02`, the writer and full fresh-process Native reader passed. The reader verifies the expected manifest CID, each chunk CID/length, and the full 1 GiB streaming SHA-256. Corrupting the footer of Pack 31 gave exit 41; withholding Pack 0 gave exit 10. Original files were restored after each test. Separately, one-off Babashka 1.12.218 `oracle_native_gib_stream.clj` imported all 64 Native-written Pack files and manifest into a new Otehon store, verified and recovered all blocks, and compared each decoded 1 MiB leaf against independently generated expected bytes. Its manifest CID and full SHA matched. This oracle ran on `.agent-output/native-gib-stream-author-01`; all 64 restored files and the manifest were byte-identical to `-02`. The oracle is not part of the Native gate, build or runtime fallback.

One complete second gate invocation, including compilation, 1 GiB generation, full positive read and two negative controls, reported 190.54 seconds wall time and 258,015,232 bytes maximum RSS via `/usr/bin/time -l`. Host load and caches were uncontrolled; this is not a throughput benchmark or an acceptance threshold. Inputs, logs and output are retained.

The writer publishes ordinary files in a fresh private directory and a manifest last. It has no demonstrated atomic root, WAL, fsync, crash recovery, externally trusted manifest, key admission, concurrent-truncation safety, independent node or OS-cache-loss evidence. Native read uses a caller-supplied Pack mapping and expected manifest CID. Do not interpret this synthetic GiB interoperability result as production qualification, real media power-loss evidence, or a general-purpose compressed-file writer.
