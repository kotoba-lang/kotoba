# Native Forest generation verification, 2026-11-14

`forest-generation-verify/verify` takes a physical generation path and an externally supplied expected logical manifest CID. It reads and decodes the bounded manifest, compares its CID, admits only the current fixed 1 MiB leaf / 16 leaves per Pack layout up to 1 GiB, then checks every referenced chunk's CID and length using positioned Native Forest reads. The function does not search older generations or fall back on failure. Its status is not a signed authority decision. The physical path and manifest CID are caller inputs; the function does not authenticate them or guard against concurrent mutation, path replacement, unlisted files, or provider traps.

On the dedicated Ubuntu 26.10 aarch64 guest, the pinned Native compiler built the smoke fixture and verified a copy of the previously rebooted 16,777,219-byte two-Pack published generation with expected CID `bafyreifofrzrmfqc2affepxac6oyi57owuaulr3pvmqi2dftdtfmjtxifq`. It also rejected an incorrect expected CID and invalid root path. The fixture returned result 0. A separate Native program returned 0 for an empty-file manifest with independently computed CID `bafyreiehdb6xheikadedplruniyw5mik35tnht55vlmqd547zau2aliffu`.

In a dedicated copy of the two-Pack generation, a damaged Pack 1 and a withheld Pack 1 each returned status 11; a damaged manifest returned status 4.
