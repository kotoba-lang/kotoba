# Native Forest publication process-stop boundaries, 2026-11-14

This local Linux aarch64 test used the same 16,777,219-byte / two-Pack source and expected generation as `native-forest-publish-new-evidence.md`. Two separate test-only copies of `forest-source-stage` at revision `aa258d09c05d1085a589879379759b7e4e510cd0` had a barrier inserted immediately before FS2 T (no-replace rename), or immediately after T returned and before the parent fsync. The barrier wrote a marker in the dedicated parent and waited. An external observer killed only the corresponding guest child with SIGKILL after observing the marker. This instrumentation changes the source and adds marker I/O; it is not a test of the exact uninstrumented artifact.

Before rename, the child exited 137, `gen-test` was absent and one private staging directory remained. Its `pack-0`, `pack-1` and `manifest` matched the independently retained successful generation byte-for-byte. After rename, the child exited 137, `gen-test` existed, no staging directory remained at that boundary, and all three objects matched the successful generation. Before/after instrumented Native artifact SHA-256 values were `9473982895be5edb9699cf381271813373dfafc83a4e43b2784db2df2aefd9af` and `aaa1e1c4ba5ce2aa2d5d68397a31319bbdba45c04ab297e9d6e84ff0c704edfe`; source locks were `b42ddcd77354a01c209b966c82ea15a6cde411aad512d6e19fe11324f9aebfc1` and `85812e81fb75c1445aa1fa2f1ce43cd2db3b43ad7c859c7d47a0377146f28f59`, with guest-specific paths.

Fresh processes compiled the uninstrumented source and retried each case. The pre-rename case returned 0 and published matching bytes; the post-rename case returned 95 and preserved the existing matching generation. Each case retained one orphan afterward. Status 95 alone does not establish that an existing generation has the intended content; the byte comparison was external to the API.

The test-owned injected source SHA-256 values are `875ed5e1df134f84b0252375cd4e53231e92f3f9e622b599a75edaf67d2d7e55` and `cda7d333e08fe0f9f4c9097d11138551c3fbdd0e5a96e4641b7670ca23baf7c1`. The runner and retry scripts, source copies, outputs and staging remain in the dedicated guest and `.agent-output/native-publish-crash`. This is process termination with caches intact, not a guest reboot, host-cache loss, actual I/O error, hardware power loss, mutable head update, WAL recovery or safe orphan cleanup proof. A same-identity process can interfere with staging and the source can change while read.
