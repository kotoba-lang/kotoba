# Native signed-basis fixture envelope, 2026-11-15

`awai.fs.basis-edn/read` reads the fixed outer field order of the current hosted EDN proof fixture, bounded to 16 KiB and printable ASCII, and extracts physical root, logical root, opaque commit text, issuer, key ID and exactly 64 signature bytes. It is intentionally a limited envelope reader, not a general EDN parser or a validator of the opaque commit: unsupported order, escaping, nested commit maps and other valid EDN can be refused. It must not be used by itself to admit an untrusted basis.

The macOS Native fixture obtains the actual 884-byte signed-basis proof via FS2 and CID, reads its root/issuer/key/signature from those bytes, and verifies the signature with the fixture public key. It compares the extracted physical root with the previously recovered fixture root, but this comparison is not a cryptographic binding. An altered logical-root byte is parsed and its signature refused; an out-of-range signature byte and truncated proof are rejected; missing Pack is refused. The original proof and hosted extraction are documented in `native-stored-basis-20261115.md`.

The first missing-Pack control trapped because the test itself eagerly attempted to take 883 elements from an empty vector. The fixture was corrected to bound that operation; the rerun passed, including missing Pack. This is distinct from the previously documented FS2 concurrent-truncation limitation. Executable SHA-256 `2c1ceefdc4bd321b67a117fae9f4f48ab25d1a2ad8a54093fad13fc1dc0d62f7`, KSL1 lock `8474c43f7c41de28e89215ccb1fcfee9d41dbb28ee6d33c96beaade48b02af63`. Local outputs remain in `.agent-output/native-basis-edn-20261115/`; the focused test is not in CI.

The logical commit remains opaque: its syntax is not fully checked and its canonical root is not recomputed. Issuer-to-public-key authorization, signed-basis admission, logical-to-physical/catalog binding, real policy/receipt, concurrency and OS-cache-loss recovery remain open. The fixture uses a public test key and identity encryption.
