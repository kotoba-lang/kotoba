# Native archive digest before Prolly lookup, 2026-11-15

`forest-file/verify-archive` performs bounded 256 KiB FS2 positioned reads over a 64-byte to 32 MiB file, checks the supplied size before and after, and compares streaming SHA-256 with the caller-supplied expected digest. `prolly-tree/lookup-verified` checks every listed archive before its existing CID-checked lookup. Expected digests must come from an independently authenticated catalog; these functions do not authenticate that catalog. They do not pin an open file or exclude concurrent mutation between checks and reads, and a concurrent truncation can still terminate some FS2 providers. This is not a snapshot, full Forest/CAR structural validation, crash durability, or OS-cache-loss proof.

The macOS Native fixture verifies the 319-byte synthetic branch archive and the original 41,181-byte Otehon Pack, then traverses branch to actual leaf and checks its value. It also verifies an independent 1,048,922-byte Forest file (SHA-256 `ee5c2c5c601e5f24cbf087ac73f8e9cfdd3bfa3002445e426b48a9756e6c0d50`) across five bounded reads. A wrong expected digest is refused. Flipping byte 20 in the synthetic archive's otherwise unselected CAR-header frame, previously invisible to selected-block lookup, makes the verified lookup fail (fixture exit 62). The original files were restored after the control. Missing original Pack remains refused.
