# Cooperative Native Forest export, 2026-11-14

`forest-export/export-new` holds the existing local cooperative writer lock while `forest-head/recover-held` parses HEAD and verifies the caller-supplied CID and generation. It rereads and validates the manifest, checks every returned chunk against its CID, writes into a fresh private directory, syncs the file and directory, and publishes with no-replace rename followed by directory sync. Output names are restricted to `file-` followed by lowercase letters, digits or hyphens. Failed stages remain for inspection. A status 112 rename failure can include a malformed response; status 113 after rename or status 102 on unlock means outcome may be uncertain. A provider trap can terminate the process.

On the dedicated Ubuntu 26.10 aarch64 guest, the Native smoke exported a one-byte generation and its output matched the source by `cmp` and SHA-256 `22adaf058a2cb668b15cb4c1f30e7cc720bbe38c146544169db35fbf630389c4`. Repeating into the existing destination returned 112 and left the bytes intact; wrong expected CID returned 105 and did not publish; invalid name returned 1. Artifact and guest source-lock SHA-256 were `c64e940b764e1f98801707d9b14769f7112ccd9cd5e13da73df7136e7660633e` and `fdaad2ef6423ddb5ceec5d85195500e304cfb9701223851792d2678dbec63a63`.

A separate 16,777,219-byte / two-Pack generation exported with `cmp` and source/output SHA-256 `f8b19f9def6dc033fedaf9a84c0f472396e056aac5bc150db9d6a469e277344b` matching. A copy with the second Pack's footer altered returned 106 before publication, and no output file was present. Artifact and lock SHA-256 were `fe4de40301818a2a5178f8240441326bf594ef176f0007436126cbf999d34dbe` and `60db881e602bb5841f0e03517b6d3d9b1bad8f16d287fae323a4d5181f53c43c`. An empty manifest exported a zero-byte file; its artifact and lock hashes were `c98bde15e467ea924b2f91242b213bd861ed141194daff5cc4e2bb0f1a5c4de8` and `d149793ad2d32ac0f288d69013f5c3fd6fef8c22c565160720bbc10faa93a494`.

While a separate process held the stable writer flock, the two-Pack artifact returned busy status 104 without creating the destination. This verifies lock contention refusal, not hostile-writer protection.

This is a bounded library primitive, not a product-runtime integration or a signed-authority implementation. The caller authenticates the expected CID, and all local writers and collectors must use the same stable lock inode; same-identity interference, concurrent noncooperating mutation and provider traps are not excluded. It does not provide WAL replay, rollback protection, hostile or distributed fencing, automatic orphan cleanup, crash-point qualification or physical power-loss proof. The larger separate 1 GiB experiment used a test-only extractor, not this export API.
