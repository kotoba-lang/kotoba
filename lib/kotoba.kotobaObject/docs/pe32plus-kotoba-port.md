## All public entries and typed results

All ten original PE export names remain. The four former constant values are
now explicit zero-argument typed accessors; native consumers must adapt this
API together with the fallible record functions.

| Entry | Typed API / retained meaning |
| --- | --- |
| `machine-codes []` | Document map, x86-64=0x8664 and AArch64=0xaa64 |
| `subsystem-codes []` | Document map, EFI application=10 |
| `max-image-bytes []` | i64, original 64 MiB limit |
| `max-section-count []` | i64, original 32-section limit |
| `little-endian [value width]` | Natural-number document, widths 1..8, high-bit truncation |
| `align-up [value alignment]` | Natural-number document, positive power-of-two i64 alignment |
| `pad-to [bytes size]` | Byte vector and i64 allocation within the original image limit |
| `encode-section-header [options]` | Complete 40-byte section record |
| `encode-optional-header [options]` | Complete 240-byte record, all 16 directories |
| `encode-image [options]` | Complete DOS/PE/COFF/optional/section/raw image |

Record/helper APIs return `:kotoba.object.pe32plus/result`: `bytes`, `value`,
`error`, `field`. Only `error=:ok` permits using either output. Align returns
the number document in `value`; serializers/padding return bytes. Errors
return no partial bytes/value and must be propagated, not coerced to a vector.

## Full natural-number semantics

PE's existing `little-endian` accepts every width 1..8 and truncates high bits;
it is not ELF/Mach-O's strict representable-width helper. This distinction is
preserved. Ordinary nonnegative i64 documents and
`{:kotoba.object/unsigned [low32 next32 ...]}` represent all natural numbers.
The vector is nonempty and every limb is in 0..4294967295, least significant
first. `{:elf64/u64 [low32 high32]}` is also accepted. Leading zero limbs are
normalized, and results fitting i64 become scalar documents. Higher values
remain explicit limb documents. No new small-value-only or unsigned64-only
domain replaces the former integer semantics.

Shared `unsigned/parse`, `little-endian`, `align-up` return
`:kotoba.object.unsigned/result` with `words`, `bytes`, `value`, `error`.
Parsing validates every limb. Serialization reads only the low requested
bytes, with shifts inside u32 limbs. Alignment adds alignment-1 with complete
carry propagation, then clears the low power-of-two bits and normalizes. It
retains arbitrarily large natural inputs while alignment itself has the
original positive machine-integer power-of-two domain. No intermediate wide
product or host numeric conversion is needed.

Image placement uses checked i64 arithmetic for bounded raw regions and u32
section fields, and full natural comparison/alignment for image-size. Existing
optional-field serialization/truncation semantics are retained; these helpers
do not independently qualify a loader's acceptance of arbitrary caller policy.

## Complete record and image path

Section names retain the 1..8 printable ASCII byte rule, encoded directly from
validated UTF-8 bytes. All five section numeric fields retain unsigned32
admission. The optional header retains all fixed fields/defaults, 64-bit image
base/stack/heap values, and all sixteen directory RVA/size pairs. Missing
directory entries are zero; explicit malformed entries refuse. Numeric index
maps and vectors are accepted, with unused entries ignored. Missing image
options take reference defaults; explicit null fields are not silently replaced.

The image path retains the original machine/subsystem choices and section/file
limits. It checks canonical padded raw sizes, raw overlap, aligned RVAs,
mapped-header exclusion, rounded virtual-span overlap, image coverage and image
alignment. Section headers preserve caller order; the first input section still
supplies text size. Raw payloads use a stable order by file offset, with bounded
gaps and padding. DOS signature/e_lfanew, PE signature, complete COFF, optional
and every section record are materialized before the complete raw payload.
No one-section-only or frozen-RVA shortcut replaces this path.

A source field ledger read matching ten-name exports, the fixed 112-byte
optional portion, 16*(4+4) directory bytes and 40-byte section layout. It did
not execute an encoder. Record layouts were compared with the primary
[Microsoft PE format specification](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format).
The 32/64 MiB caps are this component's retained policy, not a general PE limit.

## Native integration still required

Arbitrary-precision documents, typed result/accessor APIs, malformed byte/options
refusals and early allocation/overflow refusals are explicit port changes.
Historical diagnostic precedence is not claimed identical. Existing suites
were read, not executed. Allocation, parser/type support, generated bytes,
positive/refusal/resource behavior, Definition CIDs and native PE/EFI consumer
integration remain unqualified. No PE image was produced or booted.

The current ELF candidate also fixes a computed record selector to literal
branches required by the owning validator. The twelve Linux-static source
candidates were re-read with that selector inventory and had no such findings;
this is still source review, not native admission. The complete
[Mach-O canonical source candidate](macho64-kotoba-port.md) is now present.
Final native image assembly, owning-main/source/lock integration and
whole compiler self-rebuild remain open. The removed legacy CI stays retired
in the draft; no native CDCI success, service or production route is claimed.
