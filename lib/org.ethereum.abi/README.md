# org-ethereum-abi

`ethereum.abi` — the **Ethereum contract ABI argument codec**, as portable
`.cljc`. Static types, dynamic types, fixed and dynamic arrays, and tuples,
at any nesting.

Split out rather than written inside a consumer for the same reason
[`org-ietf-blake2`](https://github.com/kotoba-lang/org-ietf-blake2) was: the
first user is `cloud-filecoin`, but nothing about head/tail encoding is
Filecoin's. This workspace already has
[`base-l2`](https://github.com/kotoba-lang/base-l2)'s `abi.clj`, which is
JVM-only (it computes selectors, so it needs keccak) and throws on arrays and
tuples — and the contracts of Filecoin Onchain Cloud take both.

## Usage

```clojure
(require '[ethereum.abi :as abi])

(abi/encode-hex ["uint256" "address"]
                [42 "0xBADd0B92C1c71d02E7d520f64c0876538fa2557F"])
;; => "0x000…02a000…badd0b92c1c71d02e7d520f64c0876538fa2557f"

(abi/encode-call-hex "0xa9059cbb"          ; transfer(address,uint256)
                     ["address" "uint256"]
                     [to "1000000000000000000"])

(abi/decode ["(uint256,bytes)[]"] data)
;; => [[["1" [0xde 0xad]] ["2" [0xbe 0xef]]]]
```

## Design

**No keccak, and therefore no `function-selector`.** A selector is
`keccak256(signature)[0..4]`, and the only keccak in this workspace
(`eth-crypto.core/keccak256`) is JVM-only on purpose — its ClojureScript
branch throws rather than silently truncating to 32 bits, since every JS
bitwise operator does. Pulling that in would make this library JVM-only too.
So `encode-call` takes the selector as an argument. Callers keep theirs as
constants beside the signature that produced them and check them in a
JVM-only test, which also puts the signature where a reader can see it.

**Integers are decimal strings.** A `uint256` is four times wider than the
JVM's widest primitive. The platform big-integer appears only in
`ethereum.abi.word`, which is the one file that knows which runtime it is on.

**Out-of-range values are refused, not wrapped.** Reducing mod 2^256 turns a
caller's mistake into a well-formed call that moves a different amount.

**Signed means two's complement over the full word** — `-1` is thirty-two
`0xff` bytes. Filecoin's `big.Int` in the sibling `io-filecoin` is
sign-magnitude, where `-1` is two bytes. They are easy to confuse and wrong in
both directions.

## What is easy to get wrong, and what this is for

Encoding is head/tail, not concatenation. Each argument contributes a 32-byte
head; a dynamic argument's head is an *offset* and its value lives in a tail
block. Which types are dynamic is structural — `bytes`, `string` and `T[]`
always are; a tuple is dynamic if any component is; `T[k]` is dynamic if `T`
is. So `bytes32[2]` is static and `bytes[2]` is not, despite both having a
fixed length.

Offsets are relative to the start of the **block they appear in**, not the
call. Inside a dynamic array's tail the element offsets restart from that
array's base. This is invisible with one argument and wrong with two.

None of these mistakes produce an error. The ABI has no lengths or tags at
the argument level, so a decoder reads whatever the offsets point at.

## Verification

The vectors are **viem's**, generated by `testdata/gen_vectors.cljk` from
`encodeAbiParameters` — the encoder the Ethereum tooling world checks against,
and not this one. Thirty-seven cases chosen for the failures that simple ones
hide: two dynamic arguments in a row, a static tuple beside a dynamic one, a
fixed-length array of a dynamic type, nesting where inner offsets restart, and
lengths that are not multiples of 32.

Decoding is checked against those same bytes rather than against this
library's own output, so a matching pair of bugs cannot pass.

The tuple cases carry an explicit viem parameter spec written by hand, because
viem does not accept the `(a,b)` shorthand. That is deliberate: if the two
spellings disagree about what `(uint256,bytes)` means, the test fails — which
it would not if one were derived from the other.

Both runtimes run the whole suite. **130 assertions, green on both.**

```sh
kbb -M:test        # JVM
npm run test:cljs      # nbb
npm install && npm run vectors   # regenerate from viem
```

## What is not here

- **Selectors.** See above; pass your own.
- **Event log decoding.** Indexed topics have different rules (dynamic types
  are hashed, not stored), and getting that wrong reads a hash as a value.
- **Errors and revert reasons**, which are selector-prefixed like calls but
  need an error registry to be worth anything.
- **`fixed`/`ufixed`.** Solidity does not implement them either.
