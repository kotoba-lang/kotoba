# kami-mangaka-scene

Zero-dependency portable CLJC restoration of the **Rust** `kami-mangaka-scene`
crate — a headless 3D scene composition facade for mangaka.etzhayyim.com
(`kami-vrm` + `kami-scene-graph` + `kami-render` + `kami-postfx`, driven by
the `lg_mangaka.compose_scene_3d` Pregel graph). Restored from
`kotoba-lang/kami-engine`'s `kami-mangaka-scene/` subtree, deleted in
[PR #82](https://github.com/kotoba-lang/kami-engine/pull/82) ("Remove Rust
workspace"), per ADR-2607010930.

**Not to be confused with [`kotoba-lang/kami-mangaka-scene-clj`](https://github.com/kotoba-lang/kami-mangaka-scene-clj)**
— that is a *different*, already-restored repo: a live Clojure authoring
tier over this Rust facade (never part of the deleted workspace, split out
of the still-existing `kami-mangaka-scene-clj/` subtree in an earlier
migration wave). This repo is the restored Rust-side counterpart whose
JSON-LD contract `kami-mangaka-scene-clj` was always faithful to.

## Modules restored

Every `src/*.rs` module from the original crate has a 1:1 CLJC counterpart
for its portable content:

| CLJC namespace | Ported from | Contents |
|---|---|---|
| `mangaka-scene.camera` | `camera.rs` | `ShotGrammar`, `Dof`, `CameraSpec` (+ `Default`), `LightRole`, `LightSpec` (+ `three_point_key`/`fill`/`rim`) |
| `mangaka-scene.pose` | `pose.rs` | `PoseSpec`, `BoneRotation`, `IkTarget`, `Expression` (+ `PoseSpec::rest`) |
| `mangaka-scene.lexicon` | `lexicon.rs` | `pose_preset`, `expression_preset` (+ the XYZ-intrinsic Euler->quaternion math they depend on) |
| `mangaka-scene.sim` | `sim.rs` | `FxKind` (complete — was enum-only P0 skeleton in Rust, never wired) |
| `mangaka-scene.render` | `render.rs` | `RenderPasses` (bitflags), `RenderOpts` (+ `Default`), `RenderResult` *shape* |
| `mangaka-scene.scene` | `scene.rs` | `Transform`, `EnvironmentSpec`, `Anchor`, `MangakaScene` portable subset: `new`/`set-background`/`set-camera`/`add-light`/`character-ids`/`to-jsonld`/`from-jsonld`, plus a data-only character-record + pose-resolution helper |

`src/mangaka_scene.cljk` is the root aggregator (mirrors `lib.rs`'s `pub use`
surface) plus a data-shaped `SceneError` (the original was a `thiserror`
enum; errors here are plain `{:type :message}` maps).

## What was excluded, and why

- **`renderer.rs`** — the headless wgpu render pipeline (GPU device init,
  render pipelines, WGSL shader modules, PNG texture readback). Inherently
  native: requires a GPU.
- **`web.rs`** — the wasm-bindgen browser preview surface, sharing
  `renderer.rs`'s wgpu state via `RenderContext`. Native/wasm-target only.
- **`py.rs`** — PyO3 bindings exposing `MangakaScene` to
  `lg_mangaka.compose_scene_3d` as the `kami_mangaka_scene` Python extension
  module, built via `maturin build --features python`.
- **`pyproject.toml`** — this crate is Rust+Python in its file layout, but
  the Python side is *not* a separate tool with its own logic: it is
  `maturin`'s packaging manifest for the PyO3 wheel (`[build-system]
  requires = ["maturin>=1.7"]`, `[tool.maturin] features = ["python"]`,
  `module-name = "kami_mangaka_scene"`). There is no Python source in the
  crate — the module is generated by `maturin` from `py.rs`. Nothing to
  port on the Python side; this is noted here rather than silently dropped.
- **`scene.rs`'s VRM-bound methods** — `load_character` (parses VRM glTF
  bytes via `kami_vrm::parse_vrm`, builds a `kami_skeleton::Skeleton`),
  `pose`'s live bone application, `tick`/`settle` (spring-bone simulation
  advancing a live `SpringSimulator`), `add_prop` (glTF byte parsing),
  `compute_node_worlds`/`walk_node` (glTF scene-graph matrix composition).
  These require the external `kami-vrm` / `kami-gltf` / `kami-skeleton`
  crates (not restored in this repo) and, for the spring simulation, are
  inherently stateful native runtime rather than portable data/logic.
  `mangaka-scene.scene`'s `pose`/`expression`/`add-character-record` are a
  *portable* stand-in: they record the same authoring-facing fields
  (`rkey`, `pose-label`, `expression`, `root-xform`) and resolve pose labels
  via `mangaka-scene.lexicon`, but do not apply rotations to a live
  skeleton — there is none here.

## Test

```bash
kbb -M:test
```

20 tests / 86 assertions, 0 failures, 0 errors. Every original Rust
`#[test]` from `tests/p1_smoke.rs` is ported 1:1 in
`test/mangaka_scene/p1_smoke_test.cljk`. `tests/p2_render.rs` (headless wgpu
render smoke tests) exercises the native-only `renderer.rs` and is not
portable — not ported. Additional CLJC-only tests cover the
`camera`/`pose`/`render`/`sim`/`scene` modules' data shapes and the euler-quat
math beyond what `p1_smoke.rs` directly exercised, plus a namespace-loads
smoke test.
