# ADR 0001 — byoubu-gpu: tier 2 as graph data for the canonical executor

- Status: accepted
- Date: 2026-08-03
- Upstream: `kotoba-lang/byoubu`, `kotoba-lang/webgpu`, `kotoba-lang/wgsl`
- Workspace ADR: `com-junkawasaki/root` `90-docs/adr/2608530000-byoubu-backdrop-catalog.edn`

## Context

`byoubu` defines a backdrop once and delivers it at whichever tier the client
can take: T0 CSS gradients, T1 a rendered SVG poster, T2 the live scene. T0 and
T1 shipped on 2026-08-02. T2 was left explicitly unbuilt, with
`generator :tier-2 :pin` nil, because nothing had been through a GPU.

The workspace 3D rule is unambiguous about how T2 must be built: WebGPU +
WGSL, through the canonical kami stack, with no second engine and no new Rust.
The risk was never whether a fullscreen shader could be written — it was
whether writing one would quietly become an app-local renderer.

## Decision

**Tier 2 is a render graph handed to `kami.webgpu`, not a renderer.**

`kami.webgpu/init!` already accepts `{:graph <EDN>}` and its frame loop runs
`:passes` in order; the engine's own default graph contains fullscreen
pipelines (`:atmosphere`, `:bloom`, `:ssao`) that draw three vertices with no
mesh and no instances. A backdrop is that shape. So `render-graph` returns one
shader, one uniform, one fullscreen pipeline, one pass — and the executor does
the rest, including its own device/adapter/resize handling.

**The one missing capability was added to the executor, not worked around.**
`build-bind` recognised exactly four uniform binds, all engine-owned buffers of
fixed size (`:uniform` 464 B, `:atmosphere-uniform` 128 B, `:ssao-uniform`
48 B, `:style-uniform` 64 B). A domain package with its own uniform had no way
to express one through the graph. `kotoba-lang/webgpu` now takes a
`:uniforms {<name> {:size n}}` graph key, binds them via `{:uniform <name>}`,
and exposes `write-uniform!`. Unknown names throw, because an unbound uniform
renders a frame of zeroes that reads as a shader bug for as long as it takes to
find the typo.

That change is general. The alternative — byoubu-gpu reaching past the executor
to `org-w3-webgpu` for its own device, pipeline and pass — is exactly the
"second renderer per app" the rule forbids, and it would have been the easier
thing to do.

**The shader is data, and most of tier 2 is testable without a GPU.**
`byoubu-gpu.shader/wgsl` builds the program with `kami.wgsl` from the scene
spec. Shader generation, uniform packing and the graph are `.cljc` with no
browser dependency, so they are unit-tested on the JVM and nbb: that the WGSL
declares what the CPU packs, that a struct field added without a packer throws
rather than writing zeroes into the tail of the buffer, that the graph uses the
executor's real pass vocabulary (`:color`, not an invented `:target`), and that
all three tiers derive the horizon from the same camera pitch.

**Structure constants are baked; colours are not.** `:ridge-count` is known at
generation time, so the ridge loop is unrolled into `ridge0…ridgeN` rather than
becoming a WGSL `for` over a uniform. A backdrop is not switched per frame, and
a specialized shader is what "the scene spec is the source" actually means.
Colours stay in the uniform so a theme can move them without a recompile.

## Alternatives considered

**Put T2 in `byoubu-ui`.** Rejected — it would put the entire kami stack behind
every page that mounts a plate, which is the property the tier split exists to
protect.

**Use the engine's `:atmosphere-uniform` rather than extending the executor.**
Rejected: its layout is the engine's, so a backdrop would have to pretend to be
an atmosphere, and the next domain package would face the same wall.

**Write the WGSL as a string.** Rejected for the reason `liquid-glass.style`
builds CSS from declaration maps: a program that is a value can be asserted on.
Two of the tests here — the ridge call not smuggling parentheses through the
identifier path, and the packer/struct agreement — only exist because the
shader is data.

**Fall back to WebGL 2.0.** Not done, and this is a real gap against the
workspace rule's "WebGPU first, WebGL 2.0 fallback". The engine's WebGL path
runs pre-transpiled GLSL — `kami.webgl.glsl` is generated by running WGSL
through naga at build time — so arbitrary WGSL cannot reach it without adding
that transpile step and the naga binary to this repo. What exists instead is
byoubu's own tier chain: `mount!` reports `:tier :poster`, and the caller keeps
`byoubu-ui`'s plate, which is the T1 still over the T0 gradients. That is a
complete backdrop rather than a blank canvas, but it is not the WebGL 2.0 path
the rule asks for, and it should not be described as one.

## Consequences

- Tier 2 adds ~200 lines of domain code and one general capability to the
  shared executor. No new engine, no Rust, no per-app renderer.
- Any other domain package that needs its own uniform now can have one.
- The GPU-free layers are covered by tests; the device half is covered only by
  what a browser actually shows, which is why the demo page exposes its tier,
  frame count and a content-band sample to `window.byoubuGpu`.
- No WebGL 2.0 path for the live scene. Recorded above as a gap, not a
  decision to leave undocumented.
